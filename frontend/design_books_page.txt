## Design Philosophy

The redesign follows three principles: maximum whitespace, clear visual hierarchy, and every page having a single clear purpose. No cramped sidebars, no information overload. Think of it as a library — calm, organized, intentional.

---

## Spacing & Layout System

Use an 8px base unit throughout. This means all padding, margin, and gap values are multiples of 8: 8, 16, 24, 32, 48, 64, 96. Never use arbitrary values like 13px or 22px.

Page max-width is 1200px, centered, with 24px horizontal padding on mobile and 48px on desktop. The reading column (for detail pages and text-heavy content) is capped at 720px. The dashboard content area is capped at 960px.

Grid system uses CSS Grid exclusively — no Bootstrap columns. Standard layouts are 12-column on desktop, 4-column on tablet, 1-column on mobile. Component grids use auto-fill with minmax so they reflow naturally.

---

## Color & Typography

One neutral palette. Background is near-white (#FAFAF9). Surface (cards, inputs) is white (#FFFFFF). Border is a very light gray (#E8E6E1). Text primary is near-black (#1A1917). Text secondary is medium gray (#6B6963). Accent is a single brand color — use one, not five.

Typography scale: display 48px / 500 weight, heading 32px / 500, subheading 20px / 500, body 16px / 400 / line-height 1.7, small 13px / 400. Font is Inter or system-ui. Never bold anything at 700 inside body copy.

## Page Designs

### Landing Page (`/`)

Currently HomePage.jsx exists but is not routed. Route it. This page should be the primary conversion surface.

Structure from top to bottom: Hero section, Social proof strip, Feature highlights (3 cards), How it works (3 steps), CTA section. No sidebar. No catalog preview on this page — that belongs at `/books`.

Hero section occupies 80vh minimum. Heading is large (48px display), subtext is 20px, two buttons side by side (primary: Browse Books, secondary: Learn More). Hero background is white with a subtle geometric pattern or just clean whitespace — no stock photos, no gradients.

Social proof strip is a horizontal scrolling marquee of 5–6 stats or logos. Height 64px. Background is the accent color at 5% opacity.

Feature highlights: 3-column grid of cards. Each card has an icon (24px, not 48px), a short heading (18px), and 2 sentences of body text. Cards have no shadow — just a 1px border and 32px padding.

How it works: numbered steps 01, 02, 03 displayed horizontally on desktop, stacked on mobile. Each step has a large muted number, a heading, and one sentence. No icons needed here — the numbers are the visual element.

CTA section: centered, 96px vertical padding, heading + two buttons. Background is the accent color at full saturation with white text.

## API Layer (Frontend — Backend Compatible)

Create a single `src/api/` folder. Every file in it talks to one resource. All files import from one base client.

### `src/api/client.js`

```js
import axios from 'axios';

const client = axios.create({
  baseURL: import.meta.env.VITE_API_URL || 'http://localhost:5000',
  timeout: 10000,
});

client.interceptors.request.use((config) => {
  const token = localStorage.getItem('token');
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

client.interceptors.response.use(
  (res) => res,
  (err) => {
    if (err.response?.status === 401) {
      localStorage.removeItem('token');
      window.location.href = '/login';
    }
    // Normalize error shape — backend may return { error } or { message }
    const message =
      err.response?.data?.error ||
      err.response?.data?.message ||
      'Something went wrong';
    return Promise.reject(new Error(message));
  }
);

export default client;
```

### `src/api/books.api.js`

```js
import client from './client';

// Query params: page, limit, category, available, search, sortBy, order
export const getBooks = (params = {}) =>
  client.get('/api/books', { params }).then((r) => {
    const { books, total, page, limit } = r.data;
    // Normalize to frontend pagination shape
    const totalPages = Math.ceil(total / limit);
    return {
      books,
      pagination: {
        page,
        limit,
        total,
        totalPages,
        hasNextPage: page < totalPages,
        hasPreviousPage: page > 1,
      },
    };
  });

export const getBookById = (id) =>
  client.get(`/api/books/${id}`).then((r) => {
    // Normalize: backend returns book directly, wrap in { book }
    const raw = r.data;
    const book = raw.book ?? raw;
    // Normalize price field: backend uses rentPrice, frontend uses price
    return { book: { ...book, price: book.rentPrice ?? book.price } };
  });
```

## Mismatch Fixes Summary

Every mismatch from the doc is handled in the API layer without touching the backend:

The `/api/user/me` vs `/api/profile/me` mismatch is fixed by updating all frontend calls to use `profileApi.getMyProfile()` which calls the correct path. 
The profile update response shape (`data.user` vs `{ message, profile }`) is handled in AuthContext by reading `r.profile` instead of `r.user` after a profile update.
 The book detail envelope mismatch is normalized in `getBookById` — it accepts both a direct object and a `{ book }` envelope. The pagination shape mismatch is normalized inside `getBooks` — the frontend always gets a `pagination` object with `hasNextPage`, `totalPages`, etc. The `price` vs `rentPrice` mismatch is normalized in `getBookById` by mapping `rentPrice` to `price` at the adapter layer. Sort alias mismatches (`newest`/`latest`) should be fixed on the backend by mapping them to `createdAt desc` — or temporarily add a client-side map in `getBooks` that converts `newest` to `createdAt` before sending. The error shape mismatch is handled in the axios interceptor which checks both `data.error` and `data.message` and returns a normalized `Error` object.
