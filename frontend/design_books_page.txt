The search bar moves **into the navbar** on the /books page specifically. This is a common pattern used by Amazon, Airbnb, and similar platforms — the navbar becomes the command center when you're inside a browsing experience. On all other public pages the navbar stays minimal.

### URL STATE PATTERN

All filter and search state lives in the URL via `useSearchParams`. No separate useState for filters. This gives shareable URLs, browser back/forward support, and deep linking from category cards on landing page.

```javascript
// Reading all params in BooksCatalogPage
const [searchParams, setSearchParams] = useSearchParams()

const search     = searchParams.get('search') || ''
const categories = searchParams.getAll('category')   // array
const minPrice   = searchParams.get('minPrice') || ''
const maxPrice   = searchParams.get('maxPrice') || ''
const rating     = searchParams.get('rating') || ''
const sort       = searchParams.get('sort') || 'relevance'
const page       = parseInt(searchParams.get('page') || '1')

// Updating a param without losing others
function updateParam(key, value) {
  const next = new URLSearchParams(searchParams)
  if (value) next.set(key, value)
  else next.delete(key)
  next.set('page', '1')   // reset to page 1 on filter change
  setSearchParams(next)
}
```

### DATA FLOW SUMMARY

```
URL params (useSearchParams)
  → passed into useBooks(params) custom hook
  → hook calls GET /api/books?search=X&category=Y&page=Z
  → returns { books, totalCount, totalPages, loading, error }
  → BooksCatalogPage renders FilterSidebar + ResultsBar + BookGrid + Pagination
  → any filter/search/page change updates URL → hook re-fires → grid updates
```
