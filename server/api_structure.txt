# Book Reading Club API Structure

This document reflects the current backend contract in the server app.

## Base Notes

- Base route prefix for all APIs: `/api`
- Authenticated routes use the cookie/session JWT flow already implemented in middleware.
- All error responses for touched routes follow:

```json
{ "error": "Human readable message" }
```

- Success responses use the exact shapes documented below.
- Admin routes are listed separately for future implementation status. They are not currently mounted.

---

## Auth - `/api/auth`

### `POST /api/auth/register`
Request:
```json
{ "name": "Alice", "email": "alice@example.com", "password": "secret123" }
```
Response `201`:
```json
{
  "token": "jwt-token-string",
  "user": {
    "_id": "...",
    "name": "Alice",
    "email": "alice@example.com",
    "role": "user"
  }
}
```
Errors:
- `400` if fields are missing
- `400` if email already exists

### `POST /api/auth/login`
Request:
```json
{ "email": "alice@example.com", "password": "secret123" }
```
Response `200`:
```json
{
  "token": "jwt-token-string",
  "user": {
    "_id": "...",
    "name": "Alice",
    "role": "user",
    "isSuspended": false
  }
}
```
Errors:
- `400` if email is not found
- `400` if password is wrong
- `400` if fields are missing

### `POST /api/auth/logout`
Request: none
Response `200`:
```json
{ "message": "Logged out successfully" }
```
Notes:
- Clears the auth cookie.
- This route is currently implemented and protected by auth middleware.

## Books - `/api/books`

### `GET /api/books`
Public.

Supported query params:
- `page`
- `limit`
- `category`
- `available` (`true` / `false`)
- `search` (title or author)
- `sortBy` (`rentPrice` / `averageRating` / `title`)
- `order` (`asc` / `desc`)

Response `200`:
```json
{
  "total": 200,
  "page": 1,
  "limit": 12,
  "books": [
    {
      "_id": "...",
      "title": "Book Title",
      "author": "Author Name",
      "category": "Fiction",
      "rentPrice": 12.5,
      "isAvailable": true,
      "averageRating": 4.6
    }
  ]
}
```

Public.
Response `200`:
```json
{
  "_id": "...",
  "title": "Book Title",
  "author": "Author Name",
  "description": "...",
  "category": "Fiction",
  "rentPrice": 12.5,
  "depositRequired": 25,

  "isAvailable": true,
  "averageRating": 4.6,
  "totalReviews": 18,
```

Public.

## Rentals - `/api/rentals`

### `POST /api/rentals/rent`
Requires auth.
Request:
```json
{ "bookId": "...", "durationDays": 7 }
```
Response `201`:
```json
{
  "message": "Book rented successfully",
  "rental": {
    "_id": "...",
    "book": "...",
    "startDate": "...",
    "dueDate": "...",
    "status": "active"
  }
}
```
Errors:
- `400` if book is unavailable
- `400` if user is suspended
- `400` if user hit `maxRentalsAllowed`

### `POST /api/rentals/return`
Requires auth.
Request:
```json
{ "rentalId": "..." }
```
Response `200`:
```json
{
  "message": "Book returned",
  "rental": {
    "status": "returned",
    "returnedDate": "...",
    "overdueDays": 0,
    "penaltyAmount": 0
  }
}
```
Notes:
- If returned late, status becomes `penalised`.
- `overdueDays` and `penaltyAmount` are recalculated from due date and `book.penaltyPerDay`.

## Reviews - `/api/reviews`

### `POST /api/reviews`
Requires auth.
Request:
```json
{
  "bookId": "...",
  "rentalId": "...",
  "rating": 5,
  "reviewText": "Great read"
}
```
Response `201`:
```json
{
  "message": "Review submitted",
  "review": {
    "_id": "...",
    "rating": 5,
    "isVerified": true
  }
}
```
Errors:
- `400` if rental status is not `returned`
- `409` if user already reviewed this book

### `GET /api/reviews/book/:bookId`
Public.
Supported query params:
- `page`
- `limit`
- `sortBy` (`rating` / `createdAt`)

Response `200`:
```json
{
  "averageRating": 4.6,
  "total": 18,
  "reviews": [
    {
      "user": { "name": "Alice" },
      "rating": 5,
      "reviewText": "Great read",
      "isVerified": true,
      "createdAt": "..."
    }
  ]
}
```

### `DELETE /api/reviews/:id`
Requires auth. Own review only.
Response `200`:
```json
{ "message": "Review deleted" }
```
Side effect:
- Recalculates `book.averageRating` and `book.totalReviews`.

## Middleware

### `requireAuth`
- Verifies the JWT/session cookie and attaches `req.user`.
- Applied to all auth-required routes.

### `requireAdmin`
- Checks `req.user.role === "admin"`.
- Admin routes are documented here but not implemented in the current code path.

## Key Business Logic

### Renting a book
Before creating the rental record, check:
1. `book.isAvailable === true`
2. `user.isSuspended === false`
3. `user.activeRentalsCount < user.maxRentalsAllowed`

If all pass:
- set `book.isAvailable = false`
- increment `user.activeRentalsCount`
- set `startDate = now`
- set `dueDate = now + durationDays`

### Returning a book
When returning:
- set `book.isAvailable = true`
- decrement `user.activeRentalsCount`
- calculate `overdueDays`
- calculate `penaltyAmount = overdueDays * book.penaltyPerDay`
- if `penaltyAmount > 0`, status becomes `penalised`, otherwise `returned`

### Submitting a review
Before saving:
1. verify rental exists
2. verify rental belongs to the requesting user
3. verify rental status is `returned`

After saving:
- recalculate `book.averageRating`
- update `book.totalReviews`

### Deleting a review
After deletion:
- recalculate `book.averageRating`
- recalculate `book.totalReviews`

## Notes on Data Models

### User
Current rental/deposit-related fields:
- `depositAmount`
- `depositStatus`
- `activeRentalsCount`
- `maxRentalsAllowed`
- `isSuspended`

### Book
Current rental/review-related fields:
- `rentPrice`
- `depositRequired`
- `penaltyPerDay`
- `averageRating`
- `totalReviews`

### Rental
Tracks the rental lifecycle:
- `user`
- `book`
- `status`
- `startDate`
- `dueDate`
- `returnedDate`
- `overdueDays`
- `penaltyAmount`
- `penaltyPaid`
- `depositRefunded`

### Review
Tracks the user rating for a rental/book pair:
- `user`
- `book`
- `rental`
- `rating`
- `reviewText`
- `isVerified`

Unique review rule:
- one review per `user + book`

## Standard Error Shape

All errors should use:

```json
{ "error": "Human readable message" }
```

Common HTTP status codes:
- `200` success
- `201` created
- `400` validation / bad request
- `401` unauthorized
- `403` forbidden
- `404` not found
- `409` conflict
